## Code Style
- Use TypeScript strict mode, no `any` types.
- Every function that touches payment/inventory needs a unit test.
- Use try/catch with specific error types (e.g., `InsufficientStockError`), 
  not generic Error.
- Always explain trade-offs when suggesting a schema or architecture change.


## Testing
- Run `npm test` before suggesting a commit.
- Payment and inventory logic requires 100% test coverage — no exceptions.
